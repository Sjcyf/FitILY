# ТЗ: фитнес-тренер с камерой для физкультуры

Oct 29, 2026 · @Liebe

## Цель и сценарий

Веб-приложение для телефона, которое через камеру считает правильно выполненные повторения четырёх упражнений: отжимания, приседания, пресс и планка на время. Всё работает в браузере, видео никуда не отправляется.

Сценарий занятия:

1. Преподаватель ставит телефон на штатив или опору (горизонтально или вертикально, сбоку от студента, на 2–3 м).
2. Выбирает упражнение и задаёт цель: число повторений или время планки в секундах.
3. Студент встаёт в кадр, программа проверяет, что тело видно целиком, и запускает отсчёт 3-2-1.
4. Во время выполнения программа засчитывает только повторения с правильной техникой, озвучивает счёт и подсказки.
5. В конце на экране итог: засчитано / не засчитано, причины ошибок, время.

В кадре всегда один студент. Результаты не сохраняются, только показываются на экране.

## Платформа и технологии

Выбран веб-сайт (PWA), а не нативное приложение: он открывается на любом телефоне по ссылке, его не нужно публиковать в магазинах, а Claude Code с ним справляется лучше всего.

| Часть | Решение | Зачем |
| --- | --- | --- |
| Сборка | Vite + TypeScript | Быстрый старт, типы ловят ошибки в геометрии |
| Интерфейс | React (или чистый TS, если хочется проще) | Экраны и состояние |
| Распознавание позы | MediaPipe Pose Landmarker, пакет `@mediapipe/tasks-vision`, модель **lite** | 33 точки тела, работает на телефоне в реальном времени через GPU |
| Отрисовка | Canvas поверх `<video>` | Скелет, подсветка ошибок |
| Голос и звук | Web Speech API (`speechSynthesis`) + короткий звуковой сигнал | Студент не смотрит в экран во время упражнения |
| Экран не гаснет | Screen Wake Lock API | Телефон не уснёт во время планки |
| Хостинг | GitHub Pages, Netlify или Vercel (бесплатно) | Камера в браузере работает только по HTTPS |
| Офлайн | PWA (vite-plugin-pwa), модель кэшируется | Работает в зале без интернета после первой загрузки |

Поддерживаемые браузеры: Chrome на Android, Safari на iOS 16+. Камера: тыловая по умолчанию, с переключателем на фронтальную.

## Экраны приложения

Четыре экрана, работают в горизонтальной и вертикальной ориентации (кому как удобнее), крупный шрифт, чтобы читалось с 3 м.

1. **Выбор упражнения.** Четыре большие карточки с иконкой и подсказкой, как ставить камеру. Под карточками поле «Повторений» (по умолчанию 10) или «Секунд» для планки (по умолчанию 30). Переключатель строгости: мягко / нормально / строго. Кнопка «Начать».
2. **Подготовка.** Видео с камеры, контур-подсказка «встань сюда боком», индикатор «тело видно целиком». Когда все нужные точки видны 1,5 секунды подряд, автоматически идёт отсчёт 3-2-1 (с голосом).
3. **Выполнение.**
   - Видео со скелетом: зелёные линии — всё хорошо, красные — сустав с ошибкой.
   - Огромный счётчик «7 / 20» (для планки — таймер «00:23 / 00:30»).
   - Строка подсказки: «Ниже!», «Таз провис», «Выпрямись полностью».
   - Звук: короткий сигнал на засчитанное повторение, другой — на незасчитанное; голосом номер повторения.
   - Кнопки «Пауза» и «Стоп».
4. **Итог.** Засчитано N из цели, не засчитано M, список причин с количеством («Недостаточная глубина — 3»), общее время. Кнопки «Ещё раз» и «Другое упражнение».

Дополнительно: экран отладки (скрытый, например долгое нажатие на заголовок), где выводятся текущие углы цифрами. Он нужен для подбора порогов.

## Общая логика распознавания

Каждое повторение засчитывается по углам в суставах, которые считаются из координат точек MediaPipe, и проходит через машину состояний «верх → низ → верх».

**Угол в суставе** по трём точкам A–B–C (B — вершина):

```latex
\theta = \arccos\left(\frac{\vec{BA}\cdot\vec{BC}}{|\vec{BA}|\,|\vec{BC}|}\right)
```

Правила обработки, общие для всех упражнений:

- **Сторона тела.** Камера сбоку, поэтому берётся та сторона (левая или правая), у которой выше средняя `visibility` точек.
- **Видимость.** Если нужные точки имеют `visibility` < 0,5 дольше 0,5 с, счёт ставится на паузу с подсказкой «Тебя не видно».
- **Сглаживание.** Углы сглаживаются скользящим средним по 5 кадрам (или фильтром One Euro), чтобы дрожание точек не давало ложных повторений.
- **Гистерезис.** Пороги «низа» и «верха» разнесены минимум на 40–60°, состояние меняется только при пересечении порога.
- **Минимальная длительность.** Повторение быстрее 0,6 с не засчитывается (защита от рывков и сбоев).
- **Ошибки за повторение.** Пока идёт повторение, все нарушения техники копятся во флагах. В конце: нет флагов — засчитано; есть — не засчитано, причина показывается и копится в статистику.
- **Неполная амплитуда.** Если человек начал опускаться, но не дошёл до порога «низа» и вернулся наверх, это не засчитанная попытка с причиной «недостаточная амплитуда».

**Машина состояний** (одинакова для отжиманий, приседаний и пресса): `ГОТОВ` (наверху) → при угле ниже порога спуска `ВНИЗ` → при достижении порога «низа» `НИЗ_ДОСТИГНУТ` → при возврате выше порога «верха» повторение завершено, оценка флагов, снова `ГОТОВ`.

**Строгость** меняет пороги примерно на ±10° (мягко / нормально / строго). Все пороги лежат в одном конфиг-файле на упражнение.

## Упражнения

Все четыре упражнения снимаются **строго сбоку**. Пороги ниже — стартовые значения для режима «нормально», их уточняют на калибровке. Номера точек — индексы MediaPipe Pose (левая / правая сторона).

Точки: плечо 11/12, локоть 13/14, запястье 15/16, таз 23/24, колено 25/26, щиколотка 27/28.

### Отжимания

| Что проверяем | Как считаем | Порог | Подсказка при ошибке |
| --- | --- | --- | --- |
| Низ | Угол в локте (плечо–локоть–запястье) | < 90° | «Ниже!» (недостаточная глубина) |
| Верх | Угол в локте | > 155° | «Выпрями руки» |
| Прямое тело | Угол плечо–таз–щиколотка | ≥ 160° всё повторение | «Таз провис» (таз ниже линии плечо–щиколотка) или «Таз задран» (выше) |
| Ноги прямые | Угол таз–колено–щиколотка | ≥ 160° | «Не опускай колени» |
| Положение лёжа | Наклон линии плечо–щиколотка к горизонту | < 40° | Иначе счёт не идёт (человек ещё не в упоре) |

### Приседания

| Что проверяем | Как считаем | Порог | Подсказка при ошибке |
| --- | --- | --- | --- |
| Низ | Угол в колене (таз–колено–щиколотка) | < 100° (строго: < 90°) | «Глубже!» |
| Верх | Угол в колене | > 160° | «Встань полностью» |
| Спина | Наклон линии плечо–таз к вертикали | < 50° | «Не заваливайся вперёд» |
| Пятки | Точки пятки 29/30 не поднимаются выше уровня носка 31/32 больше чем на 3 % высоты кадра | — | «Пятки на полу» (проверка опциональная, включить после тестов) |

### Пресс (подъём туловища из положения лёжа, ноги согнуты)

| Что проверяем | Как считаем | Порог | Подсказка при ошибке |
| --- | --- | --- | --- |
| Низ | Наклон линии плечо–таз к горизонту | < 20° (лопатки у пола) | «Ложись до конца» |
| Верх | Наклон линии плечо–таз к горизонту | > 70° | «Выше!» |
| Ноги согнуты | Угол таз–колено–щиколотка | 60–110° | «Согни ноги» |
| Касание коленей (опция) | Расстояние локоть–колено, делённое на длину корпуса | < 0,35 | «Локтями до коленей» |

### Планка на время

Планка — не повторения, а таймер, который идёт только пока поза правильная.

| Что проверяем | Как считаем | Порог | Подсказка при ошибке |
| --- | --- | --- | --- |
| Прямое тело | Угол плечо–таз–щиколотка | ≥ 160° | «Таз провис» / «Опусти таз» |
| Упор на предплечья | Угол в локте | 70–110° (вариант на прямых руках: > 155°, выбирается в настройках) | «Локти под плечами» |
| Горизонталь | Наклон линии плечо–щиколотка к горизонту | < 30° | Таймер не стартует |

Логика таймера: старт, когда поза правильная 1 с подряд. Нарушение короче 1 с прощается. Дольше — таймер на паузе, звучит подсказка. Если нарушение длится больше 5 с или студент лёг, подход заканчивается. В итоге: чистое время, число нарушений и их причины.

## Требования к съёмке и ограничения

Точность почти целиком зависит от того, как поставлен телефон. Эти правила стоит показать в приложении картинкой на экране выбора упражнения.

- Телефон на штативе или опоре, на высоте 30–50 см от пола (для приседаний — около 80 см). Ориентация любая: вертикальный кадр удобнее для приседаний (человек стоит), горизонтальный — для отжиманий, пресса и планки (человек лежит и в вертикальный кадр помещается только издалека).
- Студент боком к камере, на расстоянии 2–3 м, в кадре целиком от головы до стоп.
- В кадре нет других людей, свет не бьёт в камеру из-за спины студента.
- Облегающая или не слишком мешковатая одежда, контрастная с полом и стеной.

Что программа **не** умеет и обещать не должна:

- Видеть ошибки, заметные только спереди (колени внутрь при приседе, разведённые локти). Камера одна и даёт 2D-картинку.
- Работать с несколькими людьми одновременно.
- Быть судейской системой: это помощник, и спорные повторения остаются на решение преподавателя.

Слабые старые телефоны могут выдавать 10–15 кадров в секунду. Для отжиманий и приседаний в обычном темпе этого хватает, для очень быстрого темпа — нет.

## Структура проекта

Главный принцип: каждое упражнение — отдельный модуль с одинаковым интерфейсом. Новое упражнение добавляется одним файлом без правки остального кода.

```
src/
  pose/
    poseDetector.ts      // загрузка MediaPipe, цикл обработки кадров
    geometry.ts          // углы, наклон к горизонту/вертикали, расстояния
    smoothing.ts         // скользящее среднее / One Euro фильтр
    side.ts              // выбор видимой стороны тела
  exercises/
    types.ts             // интерфейс Exercise
    pushup.ts
    squat.ts
    situp.ts
    plank.ts
    config.ts            // все пороги + уровни строгости
  session/
    repCounter.ts        // машина состояний верх/низ/верх
    holdTimer.ts         // таймер для планки
  feedback/
    voice.ts             // озвучка счёта и подсказок
    sounds.ts            // сигналы «засчитано» / «не засчитано»
  ui/
    SelectScreen.tsx
    PrepareScreen.tsx
    WorkoutScreen.tsx
    ResultScreen.tsx
    DebugOverlay.tsx
    SkeletonCanvas.tsx
  App.tsx
```

Интерфейс упражнения (общая идея):

```
interface Exercise {
  id: string;
  title: string;
  mode: 'reps' | 'hold';
  requiredLandmarks: number[];
  computeMetrics(landmarks, side): Metrics;   // углы для этого кадра
  phase(metrics): 'up' | 'down' | 'between'; // для reps
  checkForm(metrics): FormError[];            // нарушения в этом кадре
}
```

Логика упражнений (geometry, repCounter, exercises) не должна зависеть от React. Тогда её можно покрыть тестами на записанных данных.

## Этапы разработки в Claude Code

Перед началом скачайте этот документ в Markdown и положите в корень проекта как `SPEC.md`. В начале каждой сессии пишите Claude Code «прочитай SPEC.md». Каждый этап — отдельная задача; проверяйте результат на телефоне, прежде чем идти дальше.

1. **Каркас и камера.** «Создай проект Vite + React + TypeScript по SPEC.md. Сделай экран с видео с тыловой камеры телефона в горизонтальной ориентации. Добавь @vitejs/plugin-basic-ssl и запуск с --host, чтобы я мог открыть сайт с телефона по локальной сети через HTTPS.»
2. **Поза и скелет.** «Подключи MediaPipe Pose Landmarker (lite, GPU) и рисуй скелет на canvas поверх видео. Выведи в углу FPS.»
3. **Геометрия и экран отладки.** «Сделай geometry.ts, smoothing.ts, side.ts и DebugOverlay, который показывает углы в локте, колене, тазу и наклоны корпуса. Напиши юнит-тесты на geometry.ts (Vitest).»
4. **Приседания целиком.** «Реализуй repCounter (машина состояний из SPEC.md) и упражнение squat с проверками техники. Счётчик на экране, подсказки текстом.» На этом этапе впервые проверьте на живом человеке.
5. **Отжимания и пресс.** «Добавь pushup и situp по таблицам из SPEC.md, используя тот же repCounter.»
6. **Планка.** «Реализуй holdTimer и plank: таймер идёт только при правильной позе, прощение нарушений до 1 с, конец подхода после 5 с нарушения.»
7. **Экраны и сценарий.** «Сделай экраны выбора, подготовки (проверка видимости тела + отсчёт 3-2-1), выполнения и итога по SPEC.md, с настройкой строгости.»
8. **Голос и звук.** «Добавь озвучку счёта и подсказок на русском через speechSynthesis и звуковые сигналы. Не повторяй одну подсказку чаще раза в 3 секунды. Включи Wake Lock.»
9. **PWA и публикация.** «Сделай приложение PWA с офлайн-кэшем модели и задеплой на GitHub Pages.»
10. **Калибровка.** Прогон на 5–10 людях и подстройка порогов в config.ts (следующий раздел).

Совет: если что-то считается неправильно, давайте Claude Code конкретику из экрана отладки — «в нижней точке приседа угол колена 105°, а засчитывается только ниже 100°».

## Тестирование и калибровка

Цель: на правильно поставленной камере программа совпадает с подсчётом преподавателя минимум в 90 % повторений.

- [ ] Записать на телефон по 2–3 видео каждого упражнения от 5–10 разных людей: правильно, с типичными ошибками, в разном темпе.
- [ ] Добавить в приложение режим «загрузить видео вместо камеры», чтобы прогонять записи повторно без людей.
- [ ] Для каждой записи преподаватель вручную отмечает, сколько повторений правильных, и сравнивает с программой.
- [ ] Подогнать пороги в config.ts по ложным срабатываниям: засчитано лишнее — порог строже, не засчитано правильное — мягче.
- [ ] Проверить на 2–3 разных телефонах (Android и iPhone), при разном освещении зала.
- [ ] Проверить крайние случаи: студент выходит из кадра, второй человек проходит сзади, телефон упал.
